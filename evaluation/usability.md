# ブラウザ版の使い勝手の確認（v0.2.4 〜 v0.3.2）の記録

ブラウザ版（<https://ozko00.github.io/setsuzei/>）を v0.3.0 で作り直したときと、そのあとの v0.3.1・v0.3.2 で、「初めて使う人が、年内に何をすればいくら税金が減るかを知ることができるか」を確かめた記録です。

**先に、この記録の限界**（くわしくは最後の節）:

- 利用者役は**人間ではなく AI エージェント**です。人間の利用者で確かめたものではありません。
- 「確信度」は、利用者役の自己申告です。測定値ではありません。
- 各回は、人物像ごとに **1 回ずつ**しか実行していません。同じ画面でも、実行するたびに操作や感想は揺れます。回と回の小さな差に意味があるとは言えません。

## 方法

### 利用者役

- 毎回、新しく起動した AI エージェント（Anthropic の Claude。Claude Code のサブエージェントとして起動し、モデルは Sonnet を指定）。前の回の記憶は持っていません。
- 渡したのは、人物像と課題と、ブラウザの操作方法だけです。画面の使い方、正解、このプロジェクトの説明は渡していません。
- リポジトリや、ほかのファイルを読むことは禁止しました（守ったかどうかは、報告の内容からしか確かめていません）。

### 課題

> 「年末（12 月 31 日）までに、あと何をすればいくら税金が減るのか」を、このページで知ること。

### 渡した文面（人物像とフォルダだけ差し替え）

> あなたには、ある Web ページを「初めて使う一般の利用者」の役で実際に操作してもらいます。使い勝手の調査です。ページの作りや正解は誰も教えません。画面に出ていることだけを頼りに進めてください。
>
> （人物像。「この人になりきる。ここに書いていないことは知らない」）
>
> （課題）
>
> （ブラウザの操作方法。下の「操作の道具」のコマンド）
>
> 決まり:
> - 使ってよいのは上のコマンドと、look が保存した画像を見ることだけ。リポジトリやほかのファイルを読まない、検索しない、ほかのページを自分で開かない（画面上のリンクを押すのはよい）。
> - 普通の人がやるように進める。画面の説明を読んでも分からなければ、分からないまま、その人がやりそうな行動をとる（推測で入れる、空のままにする、あきらめる、など）。人物像に書かれていない税の知識で補わない。
> - 人物像にある事実は、画面で聞かれていると自分が判断した欄にだけ入れる。
> - 操作は多くても 60 回くらいまで。この人が「分かった」と思えたか、「これ以上は無理」と思ったら終える。
>
> 最後に報告すること: 1. 得た答え（やること・払う額・減る税額を、画面の数字のまま） 2. 入力した内容 3. つまずいた箇所 4. 分からなかった言葉 5. 答えへの確信度（0〜100%）と理由 6. 感想

### 操作の道具

[`scripts/persona-browser.mjs`](../scripts/persona-browser.mjs)。ヘッドレスの Chrome を 1 つ起動してページを開き、「画面を見る・座標を押す・文字を打つ」だけを受け付けます。操作はすべて記録します（`log.jsonl`）。依存パッケージは使いません（Node.js 22 以上と Chrome / Chromium が必要）。

```sh
# 起動（docs/ を配信して、そのページを開く。--mobile でスマホの大きさ）
node scripts/persona-browser.mjs serve --docs docs --dir /tmp/persona-p1
node scripts/persona-browser.mjs serve --docs docs --dir /tmp/persona-p2 --mobile

# 利用者役が使うコマンド
node scripts/persona-browser.mjs /tmp/persona-p1 look            # 画面を画像に保存し、見えている文字と、押せるものの位置を出す
node scripts/persona-browser.mjs /tmp/persona-p1 click 341 478   # その位置を押す
node scripts/persona-browser.mjs /tmp/persona-p1 type 480万      # カーソルのある欄に打つ
node scripts/persona-browser.mjs /tmp/persona-p1 clear           # 欄の中身を消す
node scripts/persona-browser.mjs /tmp/persona-p1 key Tab         # Enter / Tab / Backspace / ArrowDown など
node scripts/persona-browser.mjs /tmp/persona-p1 scroll 400      # 下へ送る（負の数で上へ）
node scripts/persona-browser.mjs /tmp/persona-p1 options 341 735 # 選択欄の選択肢を見る
node scripts/persona-browser.mjs /tmp/persona-p1 choose 341 735 青色 65万円

# 確認する側が使うコマンド
node scripts/persona-browser.mjs /tmp/persona-p1 dump            # 入力欄の値と、結果の文面をすべて出す
node scripts/persona-browser.mjs /tmp/persona-p1 stop            # 終了する
```

変更前の画面で試すには、その版の `docs/` を取り出して `--docs` に渡します（例: `git archive v0.2.4 docs | tar -x -C /tmp/before`）。

`look` が出す文字は、画面に見えている範囲のものだけです（スクロールしないと先は読めません）。入力欄・ボタン・リンクには押せる位置の座標を添えます。これは、画像だけから座標を読み取る誤りを減らすためで、人間が画面を見るのと同じではありません。

### 記録したものと、正しさの判定

- **操作数**: 記録（`log.jsonl`）から数えました。「全体」は look・scroll を含む全コマンド、「押す・打つ」は click・type・clear・key・choose の数です。
- **得た答え**: 利用者役の報告のうち「いくら払うと、いくら税金が減る」。
- **正しさ**: 利用者役が終わったあと、`dump` で画面の入力欄の値と結果を読み取り、人物像の正しい入力で CLI（`setsuzei --json`）を実行した結果と突き合わせました。「一致」は、画面の払う額・減る税額が CLI と同じという意味です。
  - 正しい入力（例）: P1 は `--revenue 480万 --expenses 75万 --blue 65 --social-insurance 59万 --furusato-paid 1万`、P2 は `--salary 620万 --revenue 90万 --expenses 12万 --misc --social-insurance 91.2万 --ideco-paid 14.4万 --furusato-paid 3万`。
  - v0.3.0 からは、ブラウザ版は「いま加入していない小規模企業共済」を合計に入れないので、CLI は `--kyosai-add 0` を付けて比べています。v0.3.1 からは、減る税額が自己負担より小さい寄附も合計に入れません（P4）。
  - P5 は社会保険料の額を知らない設定なので、「正しい入力」は設定上の値（50.4 万円）です。
- **確信度**: 利用者役が報告した数字（0〜100%）をそのまま載せています。

| 1 回目 | 結果の先頭に「やること」の一覧がない。途中まで入力した時点の数字（社会保険料 0 円の前提）を信じそうになる。結果の枠だけ別にスクロールする。画面の下の帯が入力欄に重なって押し間違える。注意書きに「CLI は --ideco-add、JSON は …」が出る | v0.3.0: 3 問から始め、仮に置いた値を結果に示す。結果の先頭を「年内にやること」に。結果の枠の内側スクロールをやめる。CLI・JSON の指定方法は画面に出さない |
| 2 回目 | 未加入の人に「小規模企業共済に 84 万円」が先頭に出て、現実的でない（P5）。免除で払っていない国民年金が、社会保険料の目安に入っていた（P4）。配偶者の欄の説明で迷う（P2）。スマホで縦に長い | v0.3.0: 未加入の共済は合計に入れず「さらに減らしたい場合」に。目安の箱に「免除の方は金額を入れる」と明記。各項目を 3 行に絞り、締切・注意は開いて読む形に。年内に出せるお金で配分 |
| 3 回目 | 「金額を入れる」を選んだだけで 0 円として計算され、数字が大きく動く（P1）。「お金は出ていく」が開かないと読めない（P5）。「47,000 円払って 47,000 円減る」が自己負担 2,000 円の説明と合わないように見える（P1）。手続きのやり方が書かれていない（P3・P5）。3,000 円払って 1,000 円減るのが得か分からない（P4） | v0.3.0 の公開前: 額を入れるまでは目安で計算。v0.3.1: やり方と公式ページへのリンク、何が手元に残るかの一文、割に合わない寄附は「やること」に入れない、用語の説明 |

### 直していない・直せていないこと

- 入力のたびに結果の数字が変わって不安になる（全員が毎回挙げた）。その場で結果が変わる作りのためで、仮に置いた値の一覧を結果の先頭に出すことで補っています。
- 細かく入力する人（P2・P3）の操作数は、作り直す前より減っていません。入力する欄の数は変えていないためです。
- v0.3.1 で書いた「やり方」を、開いて読んだ利用者役はいませんでした。読まれたかどうかは確かめられていません。
- 「やることがない」という結果になった人（P4）に、何を見せればよいかは、文面の直しでは埋まっていません。

## 限界

- **人間ではありません。** 利用者役は AI エージェントです。画面を「見る」方法も人間と違います（画像に加えて、見えている文字と押せる位置の一覧を受け取ります）。人間が同じところでつまずくとは限らず、人間がつまずくところを見落としている可能性があります。
- **確信度は自己申告です。** 同じ画面・同じ人物像でも、実行のたびに変わります。5 人の平均が数 % 動いたことを、良くなった・悪くなったの根拠にはできません。
- **各回 1 回ずつです。** 同じ条件でくり返しておらず、ばらつきの大きさを測っていません。
- **人物像は 5 つだけです。** 作った側が考えた架空の人物で、実際の利用者の分布を表していません。P3 の人物像は 3 回目から変えています（出せるお金の欄を使うかを見るため）。
- **見ているのは「答えに届くか」だけです。** 読み上げソフトでの使い勝手、実機のスマホでの操作、回線が遅いときの表示などは、この方法では確かめていません（キーボード操作・コントラスト・はみ出しは、別に `npm run test:browser` で検査しています）。
- **この記録にあるのは集計と要約です。** 利用者役の報告の全文、操作の記録、画面の画像は、リポジトリに入れていません。

この確認が役に立ったのは、「数字が良くなった」ことを示すためではなく、作った側が気づいていなかった不具合（4 回目の P2 など）を見つけるためでした。
