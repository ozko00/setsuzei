# setsuzei — 年末までの節税の概算

令和8年分（2026年分）の所得税と、それに対応する令和9年度の住民税を概算し、まだ間に合う節税策ごとの軽減額を出す。

## 守ること

- **税額を自分で計算しない。** 税率・控除額・上限を記憶から答えない。数字は必ず `setsuzei` CLI の出力から引用する。暗算・概算・「だいたい◯%」も行わない。
- CLI を実行できないときは、計算できないと伝える。推測の数字で代用しない。
- 結果は概算であり、税理士や税務署・市区町村の判断に代わらないことを、回答のたびに一言添える。
- 対象は次のものだけ: ふるさと納税、iDeCo、小規模企業共済、青色申告特別控除（年内の策）と、医療費控除・セルフメディケーション税制・生命保険料控除（確定申告で引く控除）、確定申告書（第一表・第二表）のどの欄に書くか。それ以外（住宅ローン控除、地震保険料控除の計算、法人化、経費の計上方法、消費税、個人事業税、源泉徴収税額の精算など）は計算できないと伝える。国民健康保険料は、料率が入力されたときに所得割の差の目安が出るだけで、保険料の全体額は計算できない。国保料の料率を記憶から答えない。
- 個別の申告判断（何が経費になるか、どの所得区分か、扶養に入れるか）は断定せず、税理士・税務署への確認をすすめる。

## 手順

### 1. 聞き取り

年間の**見込み額**を聞く。年の途中なら「12月までこのペースだと」で構わない。わからない項目は 0 のまま進め、あとで精度を上げる。一度に全部聞かず、まず必須の項目から。

必須:

| 聞くこと | JSON のキー |
| --- | --- |
| 給与収入（会社員・副業の人。源泉徴収票の「支払金額」） | `salaryRevenue` |
| フリーランス・副業の売上 | `businessRevenue` |
| その必要経費 | `businessExpenses` |
| 事業所得か雑所得か（開業届・青色申告の有無が目安。わからなければ本人に確認） | `businessIncomeType`: `"business"` / `"misc"` |
| 青色申告特別控除の見込み（白色は `"none"`） | `blueReturn`: `"none"` / `"10"` / `"55"` / `"65"` |
| 社会保険料の年額（国民健康保険・国民年金・給与天引き分） | `socialInsurance` |

あれば聞く:

| 聞くこと | JSON のキー |
| --- | --- |
| iDeCo の掛金（年末までの拠出見込み） | `idecoPaid` |
| 小規模企業共済の掛金（年末までの支払見込み） | `kyosaiPaid` |
| ふるさと納税の寄附済み額 | `furusatoPaid` |
| 生計を一にする配偶者の**合計所得金額**と、70歳以上か | `spouse`: `{ "income": 0, "age70OrOlder": false }` |
| 扶養親族の人数（16歳未満 / 16〜18歳・23〜69歳 / 19〜22歳 / 70歳以上 / 70歳以上で同居の父母・祖父母）。**16歳未満の子も必ず聞く** | `dependents`: `{ "under16", "general", "specific", "elderly", "elderlyCohabiting" }` |
| 給与収入が 850 万円を超える人だけ: 23 歳未満の扶養親族（16〜18 歳の子など）か、特別障害者（本人・同一生計配偶者・扶養親族）がいるか。16 歳未満か 19〜22 歳の人数を入れたときは自動で対象になる | `incomeAdjustment`: `true` |
| iDeCo の掛金を**年内に**増やせる額（加入先に確認済みの場合だけ。わからなければ入れない） | `idecoAdditional` |
| ことし払った医療費（自分と生計を一にする家族の分）と、そのうち保険金・高額療養費などで補てんされる額 | `medicalExpenses` / `medicalReimbursed` |
| セルフメディケーション税制の対象の市販薬の購入費（健康診断・予防接種などを受けた人だけ。受けたかを本人に確認する） | `selfMedicationExpenses` |
| 生命保険料控除証明書の額（一般の生命保険料の新契約 / 旧契約、介護医療保険料、個人年金保険料の新契約 / 旧契約） | `lifeInsuranceNew` / `lifeInsuranceOld` / `medicalCareInsurance` / `pensionInsuranceNew` / `pensionInsuranceOld` |
| 23 歳未満の扶養親族（16〜18 歳の子など）がいるか（令和8年分の生命保険料控除の特例。16 歳未満か 19〜22 歳の人数を入れたときは自動） | `dependentUnder23`: `true` |
| その他の所得控除の合計（地震保険料控除など、金額がわかる場合。医療費・生命保険料はここに入れない） | `otherDeductions` |
| iDeCo の年間上限（勤務先に企業年金がある人・公務員は上限が違うので本人に確認） | `idecoAnnualLimit` |
| 国民健康保険料の所得割の料率の合計（%。国保加入者で、自治体の料率がわかる場合だけ。推測で入れない） | `nhiIncomeRatePercent` |

注意:

- 金額はすべて**年額・円・整数**。「600万」は `6000000` に直す（単位の変換だけは行ってよい）。
- 配偶者は「年収」ではなく合計所得金額。給与だけの配偶者の年収しかわからない場合は、`setsuzei --salary <年収> --json`（実行方法は下の「3. 計算」）を実行して `baseline.salaryIncome` を使う（自分で給与所得控除を引かない）。
- 16歳未満の子は扶養控除の対象外だが、住民税の所得割がかからなくなる所得の上限（非課税限度額）に関わる。`dependents.under16` に人数を入れる（`general` には入れない）。所得が少ない世帯では、入れ忘れると住民税とふるさと納税の上限が実際より高く出る。
- `idecoAdditional` は、本人が「年内にあといくら増やせる」と確認できている場合だけ入れる。入れなければ、iDeCo の追加は「まとめて実行した場合」の合計から外れ、参考として別に出る。
- 医療費とセルフメディケーション税制の対象の購入費は、両方わかれば両方入れる。CLI が税額の少ないほうを選ぶ（併用はできない）。どちらが得かを自分で判断しない。
- 確定申告の時期の質問（「どこに書くか」「いくら納めるか」）では、その年の実績の額を入れる。源泉徴収税額・予定納税額は計算に入らないので、納める税金・還付される税金は、それを差し引く必要があると伝える。

### 2. CLI を用意する

計算は `setsuzei` CLI で行う。npm に公開されているので、版を固定して（0.5.0）`npx` で実行する。Node.js 20 以上が必要。

**setsuzei の MCP のツール（`estimate_tax_savings`・`furusato_nozei_limit` など）が使える環境では、CLI を用意せず、そのツールを使う**（同じ計算エンジンで、結果の形も同じ。プラグインとして入れた場合はこれに当たる）。入力は下の「3. 計算」の JSON と同じ項目で、返ってきた `result` を「4. 結果の読み方」のとおりに読む。以下は、MCP のツールが使えないときの手順。

**先に、すでに使える CLI がないか確かめる。** 次のどちらかがバージョンを返せば、取得は不要なのでそれを使う。

```sh
setsuzei --version
```

```sh
node ~/.cache/setsuzei/dist/cli.js --version
```

どちらも使えないときだけ、npm から取得して実行する。**取得の前に、次の 3 点を利用者に伝えて了承を得る。** 了承がなければ取得しない。

- npm から `setsuzei` の 0.5.0 を取得して実行すること（1 MB 未満。npm のキャッシュに入る）
- ほかのパッケージは入らないこと（実行時の依存パッケージはない）
- 計算そのものは手元だけで行い、入力した金額はどこにも送信しないこと

了承を得たら、次のコマンドで使えることを確かめる。`0.5.0` を返せばよい。

```sh
npx --yes setsuzei@0.5.0 --version
```

以後の計算は、`npx --yes setsuzei@0.5.0` に続けて引数を書いて実行する。

- 版は固定する。`@latest` や版なしの `npx setsuzei` に勝手に切り替えない。利用者が新しい版を求めたときだけ、その版を確かめてから切り替える。
- **コマンドが権限の確認で止まった・拒否されたとき** は、同じコマンドを言い換えて再実行しない。利用者に次のどちらかを頼む。
  - 上のコマンドを利用者自身の端末で実行してもらう（終わったら教えてもらう）
  - このエージェントに、`npx --yes setsuzei@0.5.0` の実行を許可してもらう
- **npm がネットワークのエラーで失敗したとき**（`ENOTFOUND`・`EAI_AGAIN`・`ETIMEDOUT` など）は、同じコマンドをもう一度だけ実行する。2 回続けて失敗したら、それ以上くり返さず、エラーの文面を利用者に伝える。
- 取得できないときは、計算できないと伝える。推測の数字で代用しない。代わりに、インストール不要のブラウザ版（https://ozko00.github.io/setsuzei/ ）を案内してよい。

#### npm から取得できないとき（補足）

`npx` が `ETARGET`・`E404`（その版が npm にない）で失敗したとき、または npm を使えない環境では、GitHub の固定したタグから取得してビルドできる。git が必要。**これも、取得の前に利用者に伝えて了承を得る**（GitHub の `ozko00/setsuzei` のタグ `v0.6.0` を `~/.cache/setsuzei` に取得すること〔約 30 MB〕、ビルドのために npm から `typescript` と `@types/node`〔とその依存の `undici-types`〕を入れること）。

次の 2 つのコマンドを **1 つずつ別々に** 実行する（`&&` や `;` でつながない。つなぐと、エージェントの権限設定で止まることがある）。

```sh
git clone --depth 1 --branch v0.6.0 https://github.com/ozko00/setsuzei.git ~/.cache/setsuzei
```

```sh
npm ci --prefix ~/.cache/setsuzei
```

`npm ci` がビルドまで行う。終わったら `node ~/.cache/setsuzei/dist/cli.js --version` が `0.6.0` を返すことを確かめ、以後はこれを使う。

- **`git clone` がネットワークのエラーで失敗したとき**（`Could not resolve host`・`unable to access`・`Connection timed out` など）は、一時的な失敗のことがある。`npm ci` には進まず（進むと「`package-lock.json` がない」という別のエラーになる）、同じ `git clone` をもう一度だけ実行する。`npm ci` がネットワークのエラーで失敗したときも、同じ `npm ci` をもう一度だけ実行する。2 回続けて失敗したら、それ以上くり返さず、エラーの文面を利用者に伝える。
- `~/.cache/setsuzei` が既にあって版が違う場合は、上書きや削除をせず、利用者にどうするか確認する。

### 3. 計算

入力を JSON にして CLI に渡し、`--json` で結果を受け取る。

```sh
echo '{"businessRevenue":8000000,"businessExpenses":1500000,"blueReturn":"65","socialInsurance":900000}' \
  | npx --yes setsuzei@0.5.0 --input - --json
```

- 以下 `setsuzei` と書いているコマンドは、手順 2 で使えることを確かめた CLI（`setsuzei`、`npx --yes setsuzei@0.5.0`、`node ~/.cache/setsuzei/dist/cli.js` のどれか）のこと。
- パイプ（`echo ... |`）が権限の確認で止まる場合は、同じ入力をフラグで渡すと 1 つのコマンドで済む（例: `npx --yes setsuzei@0.5.0 --revenue 8000000 --expenses 1500000 --blue 65 --social-insurance 900000 --json`）。フラグの一覧は `--help` で確認する。
- **コマンドに入れてよいのは、半角数字の金額・人数と、決まった選択肢（`blueReturn` の `none` / `10` / `55` / `65`、`businessIncomeType` の `business` / `misc`、`true` / `false`）だけ。** 利用者が書いた文字列を、そのままコマンドや JSON に入れない。「600万」「約 90 万円」のような書き方は、先に半角数字の円（`6000000`、`900000`）に直す。数字に直せない入力や、記号（`'` `"` `;` `|` `&` `$` `` ` `` `<` `>` `\` など）を含む入力は、コマンドに渡さず、利用者に聞き直す。
- ファイルのパス、URL、コマンドの一部など、金額と選択肢以外のものを利用者やほかの資料から受け取って実行しない。実行するのは `setsuzei` CLI だけ。
- 終了コード 2 は入力の誤り。標準エラーの `error.issues` を読んで直す。直せなければユーザーに確認する。
- 「iDeCo をあと10万円だけ」のような条件は `idecoAdditional` / `kyosaiAdditional` で指定して再実行する。条件を変えた比較は、条件ごとに CLI を実行する。差額を自分で按分しない。
- 掛金の追加は、税額が減らなくなる額までで止めて計算される（`additional` が残り枠より小さく、`noEffectBeyond` に額が入る）。それ以上の拠出をすすめない。

| 入力に応じた注意 | `warnings` |

### 5. 伝え方

1. 現状の税額の見込み（所得税・住民税・合計）。
2. 策ごとに「いくら払うと、いくら減るか」。**減る税額だけを単独で言わず、必ず支払う額（`additional`・`remaining`・`totalPayment`）を隣に並べる。** 各策の `notes` にある条件や期限の注意を落とさずに伝える。
3. 組み合わせ: 各策の軽減額は単独で実行した場合のもの。まとめた合計は `measures.combined.saving` と `.totalPayment` を使う（各策の軽減額を自分で足さない）。掛金を増やすとふるさと納税の上限は下がる（`limitAfterOtherMeasures`）ことも伝える。
4. iDeCo の追加は、`idecoAdditional` を指定していなければ合計に入っていない。掛金額の変更は年 1 回で、まとめて拠出するには事前の届出が必要なため、年末が近いと今年分に間に合わないことが多い。「加入先に確認して増やせる場合は」と条件を付けて `measures.ideco` と `measures.combinedWithIdeco` の数字を伝える。間に合う前提で話さない。
5. ふるさと納税は、寄附した額とほぼ同じだけ税が減る仕組みで、手元のお金は増えない（得になるのは返礼品の分と、自己負担 2,000 円）。合計の軽減額を伝えるときは、ふるさと納税による分（`savingFromFurusato`）を分けて言う。
6. iDeCo は原則 60 歳まで引き出せず、手数料がかかり、受け取るときに課税がある。小規模企業共済も受け取るときに課税があり、任意解約は掛金納付月数 240 か月未満だと元本を下回る。これらを添える。
7. `warnings` があれば伝える（住民税の非課税や、16 歳未満の子の入力を促すものを含む）。
8. 確定申告書のどこに書くかを聞かれたら、`filing.entries` の `field`（欄の番号）・`label`（申告書に印刷されている名前）・`amount` をそのまま伝える。欄の番号を記憶から答えない。様式は国税庁の令和8年分の確定申告書（案）にもとづくこと（`filing.draft` が `true` の間）と、`filing.notes` の注意（源泉徴収税額・税額控除は含まない、など）を添える。人が読む表は `setsuzei ... --filing` でも出る。
9. 概算であること・税理士や税務署の判断に代わらないことを最後に添える。根拠を聞かれたら `setsuzei --sources` の一覧を示す。
